# Wide EP 重叠优化实现清单

目标：同一版本交付 RoCE 与 MegaMoE 的统一流水线，以消除可避免的 SM 有效计算空泡为第一原则，实现边传边算、边算边传及 Shared 调度。以下为并列工作项，不划分阶段、优先级或层间前置版本。2026-11-03 用户已授权开始实现；性能对照固定 **P5/D5**。

## 最终调度约束

新方案方向成立，但固定的 S0/S1/S2 顺序与两个槽位不能保证充分重叠。实现采用依赖驱动的任务调度：计算资源存在兼容的就绪任务时，应推进该任务；遇到未就绪的 Routed、Shared 或归并任务时，不能把其他独立任务挡在其后。SM 忙等、额外复制和降低 GEMM 效率造成的忙碌不算消除空泡，最终仍以正确性、整层时延及服务吞吐验收。

1. **启动即推进**：首个可发送子块就绪就发出，接收 credit 提前发布；本地源 token 的 Routed 与 Shared 进入独立就绪集合，不等待无关远端 token 或全部输入打包完成。
2. **内核内选择就绪任务**：网络子块、专家 tile、Shared tile 独立粒度。Routed 的 FC1、激活/量化、FC2、节点内归并按各自依赖推进。Shared 纳入兼容的原生调度域，以受限 tile 粒度穿插；不能依赖另一个独占全 SM 的 kernel 来填补常驻 kernel 内的等待。协作 CTA、NVLink 通信和 epoch 仍须满足一致顺序与资源约束。
3. **消除隐含整批屏障**：专家计数、路由槽位和尾块封口均按子块描述，足量就绪 tile 可先计算；尾块和零贡献用明确计数/结束标记闭合。归并就绪依据对应 token/输出片段的全部本地专家贡献完成，不能仍等待整 grid 的所有 FC2 结束。
4. **提前回传可观察**：内核内发布完成片段，CPU progress 在 kernel 未退出时取得发送就绪。按所有参与写入者完成、数据可见、发布标记的顺序建立依赖；不得把发布操作排在同一长 kernel 之后。接收也须完成分片和 GPU 可见性后才标记就绪；直接供其他本地 GPU 读取时，另外满足对应可见性范围。
5. **Shared 按实际窗口调度**：每个原始 token 仅计算一次并输出独立 BF16 结果。就绪 Routed、Shared、归并按解除背压和剩余关键依赖选择，兼顾公平性；不固定把 Shared 全部放在开头或末尾，也不为保留 Shared 而让当前可用 SM 空闲。调度重排不改变 gate 次数和规定的归约/舍入语义。
6. **槽位与网络分别调度**：Dispatch 与 Return 使用独立槽位池和任务编号，允许不同槽位数；输入发送/消费完成后可复用，输出在发送及归并读取完成后才复用。有其他可用槽位时不阻塞在固定 modulo 槽位。Dispatch、Return 共享 NIC 发送能力，按输入饥饿、回传背压与公平性仲裁；控制消息必须能持续推进。分片发送可合并连续就绪区间，并限制等待合并的时间。
7. **覆盖单网络块场景**：在全部请求都处于 Decode 且 DP16 均衡的假设下，C4096 对应约 256 请求/rank；D5 主模型最多约 1536 验证 token/rank、草稿约 1280 query token/rank，实际还受调度和 Graph padding 影响。固定 2048-token 网络块可能只有一块，因此验收必须包含单块内部重叠，主模型与草稿分别选粒度。小 batch 避免为增加块数而过度切碎 GEMM。
8. **Graph 与活性**：预分配任务、队列、计数器和缓冲，固定地址，按层/重放 epoch 隔离；GPU 内的就绪选择适配静态 Graph。调度器不能占住其他任务完成依赖所需的全部资源，CPU progress 与超时退出独立推进。
9. **如实衡量剩余空泡**：逐类记录等待输入、专家依赖、槽位、credit、CPU progress、屏障与最终回传的时间。单层有用工作已耗尽而远端数据未到时，仍存在依赖下界；结合通信实际字节量、NIC/HBM/NVLink 资源竞争与任务依赖解释剩余差距。消除这种尾部的跨层/跨请求流水不作为本轮已实现能力。

- [ ] **统一接口**：对齐分支封装、实际 DeepSeek V4 adapter、MegaMoE 与传输端的任务描述、布局和完成通知。
- [ ] **就绪任务调度**：贯通 Routed、Shared、归并与数据发布的任务状态，跳过未就绪任务，保证公平、协作组一致性与无循环等待。
- [ ] **边传边算**：输入子块的激活、scale、路由信息就绪即可调度专家 tile；改造 MegaMoE 计数和调度，缩小整块等待范围。
- [ ] **边算边传**：对应 token 的节点内专家贡献全部合并后立即发布 BF16 partial，在 kernel 未退出时推进回传。
- [ ] **Shared 调度**：按可用窗口安排启动、稳态和收尾任务；只计算本 rank 原始 token，每行一次，统一外层与内核的计算所有权。
- [ ] **传输协议**：解耦接收 credit 与发送就绪，分别跟踪发送、接收和消费完成；保证 epoch、分片完成及 GPUDirect 可见性正确。
- [ ] **缓冲管理**：Dispatch、Return 独立管理生命周期，支持配置槽位数；在发送和消费结束前禁止覆盖，隔离不同层与图重放。
- [ ] **网络仲裁**：独立推进两个方向的发送/接收，协调 Dispatch 与 Return 的 NIC 竞争，避免输入饥饿、回传背压和控制消息队头阻塞。
- [ ] **减少搬运**：优化 RDMA 与原生 buffer 布局，减少输入 staging、输出临时张量和本地 partial 复制。
- [ ] **融合归并**：合并跨节点 reduction 与 Shared Add；保留 FP32 累加、中间 BF16 舍入及最终 BF16 输出，路由权重只应用一次。
- [ ] **形状与图适配**：独立选择网络、专家计算和 Shared 粒度；覆盖小 batch、尾块、padding、空 rank，并保证 CUDA Graph 调度与地址稳定。
- [ ] **负载与推进**：优化专家布局及 EPLB 映射、CPU progress 亲和性、轮询与 QP 分片，降低慢 rank 和协议等待。
- [ ] **正确性验收**：验证不同输入到达顺序、零长度传输、槽位复用、连续重放、超时退出和数值一致性。
- [ ] **性能验收**：以完整端到端请求的精度、吞吐、延迟及稳定性为验收依据。记录就绪到执行延迟、各类等待及有效计算活动，核实首个计算早于整块接收、首批回传早于 kernel 退出；单层结果仅用于定位，不替代匹配 P5/D5 条件下的 EP8/EP16 服务验证。

精度约束：Dispatch 为 MXFP8，Return 为 BF16；Routed 为 W4A8，Shared 为 W8A8。跨节点 partial 采用 FP32 求和后舍入为 BF16 routed，再与 BF16 Shared 相加得到 BF16 输出。实施过程中逐项附验收证据，尚未完成的条目保持未勾选。

## 验证与对照

- 协议覆盖改变到达顺序、双向不对称流量、零长度、尾块、空 rank、槽位压力、连续 Graph replay、不同层复用、超时退出和可见性。
- 数值覆盖主/草稿模型、独立 oracle、同精度串行参考、真实 checkpoint、EPLB 迁移，以及 Shared 与 gate 恰好一次。算法规定相同的场景要求精确一致，其他误差标准在运行前固定。
- 整模型采用完整 GSM8K 1319 题、相同八样例/seed/采样参数，沿用零 HTTP 错误和准确率下降不超过 0.5 个百分点的工程门槛，报告逐题差异及截断；长压后复验。
- 服务对照为 `1×DEP2 P + DEP8 D`、优化前 `1×DEP2 P + DEP16 D`、优化后 `1×DEP2 P + DEP16 D`，统一 P5/D5，冻结代码/镜像/语料/缓存/调度参数。
- 2026-11-03 用户进一步要求以端到端验证为主。原部署镜像的 vLLM adapter 和 DeepGEMM 与分支固定版本存在差异；部署使用最小回移并记录文件清单，补充同一新镜像关闭重叠的对照，避免将库版本变化归因于重叠调度。
- 当前执行优先级：先测已实现重叠版 DEP16，直接比较第一批 DEP8；必要启动与冒烟检查通过后先跑性能，随后补全精度、原版 DEP16 性能和同镜像关闭重叠对照。
- 总请求并发扫描 `1,8,32,64,128,256,512,1024,2048,4096`，拐点加密；记录实际 Decode 活跃请求、target/draft token 和 Graph padding，不能将 token/rank 当成请求并发。
- 同时报总输出 token/s、每张 D 卡 token/s、TTFT、TPOT、尾延迟、错误率及 GPU/NIC 指标。单 P 成为瓶颈时补充 D 侧隔离结果；每点充分预热并重复测量，原始结果使用独立 run ID。
